Guia general - Vision integral del proyecto

Resume todo el sistema de gestion de la clinica veterinaria Clinica DDSF como una solucion integral. Las guias 1 a 4 cubren cada bloque en detalle; esta las conecta.

1. Que es el sistema

Una aplicacion web Full Stack para gestionar integralmente los procesos de una clinica veterinaria: administrativos, medicos, comerciales y financieros.

  • Backend: Spring Boot (Java 21), API REST documentada en Swagger.
  • Frontend: Angular 19 (Datta Able + Bootstrap 5), con identidad de marca propia.
  • Base de datos: MySQL.
  • Despliegue: Docker y Docker Compose (MySQL + backend + frontend).

2. Los modulos y como se conectan

  • Inventario (Fase 1): medicamentos y productos, con lotes, precios, Invima, codigo, alertas y carga masiva.
  • Citas con calendario (Fase 2): agenda por veterinario, estados y reglas de no solapamiento.
  • Atencion, formulas y facturacion (Fase 3): atencion de la cita, formulacion y factura.
  • Reportes (Fase 4): informacion consolidada, exportable a PDF y Excel.
  • Despacho (Fase 5): entrega real de los medicamentos; unico punto donde se descuenta el inventario.

Idea que conecta todo: formular no descuenta inventario; el inventario solo se afecta cuando el despacho confirma la entrega. La facturacion toma servicios y medicamentos; los reportes leen facturas, movimientos y citas.

3. Seguridad y roles

El acceso se controla por perfiles, con validacion real en el backend (un filtro revisa token y rol en cada peticion), no solo ocultando menus.

  • Administrador: acceso completo.
  • Recepcion: gestion operativa y facturacion.
  • Medico: su calendario, atencion e historias.
  • DESPACHO_MEDICO: inventario en consulta y despacho.
  • Contable: reportes y facturacion en consulta.
  • JEFE_BODEGA: reportes e inventario en consulta.

4. Integridad de la informacion

  • No se eliminan registros fisicamente: se desactivan o anulan, conservando el historial.
  • Las operaciones criticas (descuento en el despacho) son transaccionales.
  • Las tarifas se conservan historicamente en la factura.
  • Los cambios de estado y de tarifa quedan en tablas de log.

7. Guion sugerido para la sustentacion

  • Levantar el sistema con docker compose up --build y abrir el frontend.
  • Iniciar sesion como administrador y mostrar el menu agrupado.
  • Inventario: catalogo, lotes y carga masiva con mas de 50 registros.
  • Citas: calendario, crear una cita y vista del medico.
  • Atencion y formulas: atender, formular e imprimir la formula en PDF.
  • Facturacion: generar la factura, registrar pagos y descargar el PDF.
  • Despacho: como DESPACHO_MEDICO, dispensar y mostrar como baja el inventario (FEFO) y el comprobante.
  • Reportes: como Contable o Jefe de bodega, generar un reporte y exportarlo a PDF y Excel.
  • Seguridad: mostrar que un rol no autorizado no puede acceder a un modulo.
  • Cerrar explicando integridad (no se borra, se anula; transacciones; historicos) y el despliegue en contenedores.
