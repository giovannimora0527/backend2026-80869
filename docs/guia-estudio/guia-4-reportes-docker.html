Guia de estudio 4 - Reportes y despliegue con Docker (Fase 4 y entregables)

Cubre dos temas: el modulo de reportes administrativos y contables (Fase 4) y el despliegue del sistema completo con Docker y Docker Compose (entregable obligatorio).

Parte A. Modulo de reportes (Fase 4)

1. Vision general

Consolida la informacion de la clinica en tres grupos: financieros, inventario y gestion medica. Todos permiten filtrar por fechas, mostrar vista previa y exportarse a PDF y Excel. Es un modulo de solo lectura: construye los reportes a partir de la informacion ya registrada (facturacion, inventario y citas).

2. Como esta hecho (idea tecnica)

Todos los reportes usan una misma estructura (titulo, subtitulo, columnas, filas y totales), que sirve tanto para la vista previa como para el PDF y el Excel. Asi la presentacion y la exportacion son genericas.

3. Catalogo de reportes

Financieros

  • Ingresos por periodo, por consultas, por venta de medicamentos, por especialidad y por veterinario.
  • Facturas por estado; pagos parciales con saldo; impuestos y descuentos; resumen por dia, mes y anio.

Inventario

  • Existencias; valor del inventario (costo y venta); agotados; stock minimo; proximos a vencer; vencidos; entradas y salidas.

Gestion medica

  • Citas por periodo; citas por estado; consultas por veterinario; consultas por especialidad; mascotas atendidas.

4. La "foto del momento"

Hay dos tipos de reporte: por periodo (ingresos, movimientos, citas), donde la fecha cambia el resultado; y foto del momento (existencias, valor, agotados, stock minimo, por vencer, vencidos), que reflejan el estado actual y no dependen del periodo. El selector de fechas aparece siempre (lo pide el enunciado), pero en los de foto del momento se muestra deshabilitado con una nota.

5. Control de acceso

Restringido a Administrador, Contable y JEFE_BODEGA. El menu solo aparece para esos perfiles y el backend rechaza las peticiones de roles no autorizados. Perfiles nuevos: Contable (financiero) y JEFE_BODEGA (inventario).

6. Como usar el modulo

  • Elegir pestana, tipo de reporte y rango de fechas.
  • "Generar": muestra la vista previa con totales.
  • "PDF" y "Excel": descargan el mismo reporte que se ve en pantalla.

7. Flujo de prueba sugerido (reportes)

  • Financieros: "Ingresos por periodo" y exportar a PDF y Excel.
  • Inventario: "Valor del inventario" (no depende de la fecha).
  • Gestion medica: "Citas por estado".
  • Entrar como Contable y como JEFE_BODEGA para mostrar el acceso restringido.

Parte B. Despliegue con Docker

8. Para que sirve Docker

Empaqueta cada parte con todo lo que necesita, de modo que el sistema corre igual en cualquier equipo sin instalar Java, Maven, Node ni MySQL. Docker Compose coordina los tres contenedores: MySQL, backend (Spring Boot) y frontend (Angular + Nginx).

9. Como esta construido

  • Cada proyecto tiene un Dockerfile de dos etapas (multi-stage): una construye y otra, mas liviana, ejecuta.
  • El docker-compose.yml declara los servicios, la red, el volumen de MySQL y los puertos.
  • El backend corre con un perfil "docker" que lee la configuracion desde variables de entorno.
  • MySQL ejecuta el dump de la base la primera vez que arranca.

10. Como se ejecuta

Desde la carpeta del backend, con los dos repositorios como carpetas hermanas:

docker compose up --build

Queda disponible en: Frontend http://localhost:4200, API http://localhost:8080/clinica/v1, Swagger /swagger-ui.html. Para detener: docker compose down; para borrar datos: docker compose down -v. El OTP del login requiere configurar el correo en un archivo .env (hay plantilla .env.example).

11. Problemas que se resolvieron

  • Referencia circular de JWT_SECRET: una propiedad no puede leerse a si misma; se uso la variable JWT_SECRET_ENV.
  • "Public Key Retrieval is not allowed" con MySQL 8: se agrego allowPublicKeyRetrieval=true a la URL de conexion.

12. Flujo de prueba sugerido (Docker)

  • Mostrar los dos Dockerfile y el docker-compose.yml.
  • Ejecutar docker compose up --build y mostrar los tres contenedores arriba.
  • Abrir el frontend e iniciar sesion; abrir Swagger.
  • Explicar que todo corre en contenedores, sin instalar nada mas que Docker.

13. Glosario

  • Contenedor: caja aislada con una parte del sistema y todo lo que necesita.
  • Imagen: plantilla a partir de la cual se crea un contenedor.
  • Dockerfile: receta para construir una imagen.
  • Docker Compose: herramienta que levanta y conecta varios contenedores.
  • Multi-stage: construccion en etapas para una imagen final liviana.
  • Volumen: almacenamiento persistente (los datos de MySQL sobreviven a reinicios).
